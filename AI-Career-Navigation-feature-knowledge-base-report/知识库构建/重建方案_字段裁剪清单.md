## 二、裁剪总原则

| 处理 | 字段类型 | 理由 |
|---|---|---|
| **必留** | 主键 / 外键（`*_id`） | 检索结果要能回溯、要能跨表打通 |
| **必留** | 业务展示字段（标题、难度、等级…） | 模型回答时要用 |
| **必留** | 合规四件套：`is_synthetic`、`claim_level`、`is_market_fact`、`display_disclaimer` | **团队红线**：展示给用户的数据必须能自证"演示数据"，否则视为把模拟当真实 |
| **必留** | `data_split` | 评测纪律：`test` 集不参与调参/演示挑选 |
| **建议保留** | `confidence`、`source_ids` | 答案引用与可信度说明要用 |
| **建议裁剪** | `schema_version`、`generated_at`、`last_verified_at`、`license_scope`、`origin`、`verification_status` | 纯审计字段。不参与检索也不参与回答；且**每多一个字段就多占一段表格宽度**，平台表格型知识库对列数有隐性限制 |
| **按需保留** | `verified_individual_page`、`page_kind`、`metadata_scope` | 见下方 2.2 —— **这三个是资源库的合规关键，必留** |

## 五、需要你拍板的 3 个问题

**Q1（重要）｜资源库要不要拆分合规字段的语义**
`learning_resources.csv` 里混了两类东西：22 条 `verified_course_metadata`（官方已核验课程）和 98 条 `public_catalog_topic_card`（公开目录话题卡）。团队红线是**这两类严禁合并标注为"官方课程"**。
三个选项：
- (a) 都放一张表，靠 `page_kind` / `metadata_scope` / `verified_individual_page` 区分 —— 表少，但依赖模型正确读取字段
- (b) 拆成两张表 → 两个知识库（"已核验课程库" + "公开目录库"）—— 最安全，但违反"每类资源一个库"的简洁性，且 22 条太稀
- (c) 都放一张表，但把 `page_kind` 的中文值直接写成"官方已核验课程" / "公开目录话题卡"，让检索能直接命中

**我倾向 (a)**，因为 (b) 让 22 条独立成库性价比太低，(c) 把展示文案写进数据字段不够干净。

**Q2｜是否需要字段中文别名**
平台表格字段名必须英文，但模型回答时需要中文。方案：在 `title` / `summary` 等文本字段里自带中文，字段名保持英文。**这样够吗？还是你希望我把字段说明也塞进某列？**

**Q3｜1500 / 600 / 22491 行是否全量上传**
- 岗位库 1500 行：其中含 `data_split=test` 的行。按评测纪律，test 集不参与演示挑选，但**可以入库**（评测时按 `data_split` 过滤）。
- 岗位技能要求库 22491 行：解析时间可能较长。
**确认全量上传，还是要我先按 `data_split` 过滤掉 test？**
