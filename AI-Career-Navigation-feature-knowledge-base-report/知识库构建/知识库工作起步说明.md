## 一、知识库怎么共享——它不是 web 项目，Git 不是载体

### 1.1 先纠正一个根本类比

你之前的项目是**自托管**模式：代码在你机器上 → docker/postgres 起服务 → 浏览器打开 localhost → 推 Git 发 PR。**知识库完全不是这个模式。**

百宝箱是**多租户 SaaS**。官方文档原话：

> 知识库是智能体与用户交互过程中的"信息管家"，统管您上传至百宝箱中的各类文档与资料，即数据仓库中存储的数据。

关键推论：**知识库的"本体"运行在蚂蚁的云服务器上**（`b.tbox.cn/inc/knowledge`），不在你 D 盘那份代码里。你的电脑关机，知识库照样在、照样能被智能体调用。

一个更贴切的类比：**它像你团队共用的一个语雀/腾讯文档空间，而不是你本机的一个数据库。**

### 1.2 共享的载体叫「空间」

平台文档里反复出现「工作空间」「当前空间下」：

| 原文出处 | 原话 |
|---|---|
| 应用概述 | 同一空间下，仅支持创建最多 **200 个智能体应用** |
| 插件发布 | 已发布的插件，可以**被空间内智能体应用添加使用** |
| 创建插件 | 调用百宝箱企业版**当前空间下**搭建发布的智能体应用 |
| 卡片配置 | 支持选择**当前空间内已发布的卡片** |
| 模板克隆 | 相关插件资源将同步复制至**使用者空间** |

**结论：「空间」就是团队工作区容器。** 里面装着智能体应用、插件、卡片、知识库、应用数据。队友在同一个空间里登录，就能看到并编辑你建的知识库。

所以你的分工应该是：

```
你在百宝箱空间内建知识库  ──→  队友在同一空间内直接看到 / 使用
                          （无需你"交付文件"）
```

### 1.3 四种"分享"要分清，别混用

| 方式 | 谁能看到 | 能改吗 | 说明 |
|---|---|---|---|
| **① 同一空间成员** | 队友 | ✅ 能看能改 | **这是团队协作的正路** |
| ② 发布智能体 | 所有用户 | ❌ 只能用 | 关联知识库后把智能体发到 Web/支付宝小程序/微信小程序/钉钉；用户是"用"知识库，不是"看"它 |
| ③ 知识库管理 API | 任何持凭证的三方系统 | ✅ 能读写 | 官方：提供一系列知识库管理 API，可"实现在三方系统中使用知识库的相关能力" |
| ④ 上架至行业应用模板 | 其他空间使用者 | 只能克隆结构 | 原文：知识库"**结构将完整克隆至使用者空间，实际数据内容不会被克隆**" |

第④条特别重要——**模板市场只克隆结构，不克隆数据**。所以别指望"上架模板"来实现团队共享。

### 1.4 ⚠️ 我查不到的一环（必须你自己确认）

我把 258 篇百宝箱文档全量检索过，**没有「空间成员管理 / 邀请协作者 / 角色权限」这一章**。文档只有六大板块：应用、插件、卡片、工作流、知识库、技能。

也就是说，「**具体怎么把队友加进空间、给什么角色、能否只读**」这个操作细节，**我手上没有权威依据，不替你编**。你必须去这两处确认：

2. 平台右下角「在线客服」

**这是你方案定稿前的前置条件**，因为它决定你是"一个人建好再共享"还是"分头建各自的部分"。

### 1.5 那 Git 到底该存什么？

Git 存**不是知识库本体**，而是"**可重建知识库的原料、配方与证据**"：

| 该进 Git | 内容 |
|---|---|
| 源数据 | 从 `knowledge_cards.csv` 转出的 Markdown / CSV（上传前的最终形态） |
| 建库配方 | 建了哪几个库、类型、字段设计、分段长度、检索策略、匹配度阈值、是否开精排 |
| 评测证据 | 命中测试用例集 + 每轮测试的命中结果 + 参数对比表 |
| 效果评估报告 | 就是你要交的**企业专项材料②**正文 |
| 配置截图 | 赛题明确要求"配置说明与操作截图" |

一句话：**云端放"活的"，Git 放"能重建的"。** 答辩现场要重建时，你手上有完整一套。

**回答你的疑问：** 你说"我记得找数据的是去找测试数据"——**方向记得没错，但理解偏了**。他不是在做"和知识库无关的测试"，而是：

- 他交付的 `matching_eval` / `path_eval` / `dialogue_eval` / `fairness_eval` / `privacy_security_eval` 确实是**给其他模块的评测集**；
- 但他**同时专门为你做了两张表**：`knowledge_cards`（知识库原料）+ `retrieval_eval`（知识库检索评测集）。

`TEAM_HANDOFF.md` 的模块依赖表也印证了这种"按模块供料"的分工方式。**所以答案是：他采集的数据不但对你有用，而且其中两张表就是专门为你准备的。**

### 2.3 具体怎么用——原料与评测集

**原料：`knowledge_cards.csv`（600 张）**

| 类别 | 数量 | 用途 |
|---|---:|---|
| `skill_level` | 300 | 60 项技能 × 5 个等级，用于"这个能力到什么程度算够用" |
| `learning_resource` | 300 | 学习资源说明卡 |

字段：`knowledge_card_id / category / title / content / keywords / related_entity_type / related_entity_id` + 一套合规元数据（`claim_level / verification_status / license_scope / is_market_fact / data_split` 等）。

**评测集：`retrieval_eval.csv`（100 条）**——这张表就是你的"评分标准答案"：

```
字段：retrieval_case_id / query / expected_card_ids / expected_source_ids
      / top_k(=5) / relevance_grade(=3) / acceptance_rule
```

`acceptance_rule` 全部是同一句：

> `expected_card_ids` 至少一项出现在 Top5 且回答引用来源 ID

**这意味着"效果评估报告"的评测口径队友已经替你定好了。** 它正好对应百宝箱「命中测试」页的功能配置（检索最大结果数默认 5 / 最小匹配度默认 0.500 / 精排默认 Top3 阈值 0.800）。

### 2.4 评测集覆盖哪五类提问

100 条 query 恰好覆盖 5 类，这直接定义了你知识库必须回答的问题域：

| 查询类型 | 条数 | 示例 |
|---|---:|---|
| 学习资源推荐 | 49 | 「统计学基础课程主题卡（advanced）适合什么水平，预计需要多长时间？」 |
| 能力等级证据 | 27 | 「如何判断Python编程等级1，需要哪些证据？」 |
| 岗位匹配解释 | 15 | 「数据分析师与Python编程在岗位匹配中如何体现？」 |
| 趋势数据解读 | 5 | 「实验与A/B测试趋势数据解释应如何向用户解释？」 |
| 隐私使用边界 | 4 | 「API设计数据使用边界应如何向用户解释？」 |

## 三、⚠️ 我发现一个数据缺陷，需要反馈给队友

### 3.1 现象

我逐条核对了 `retrieval_eval` 的 `expected_card_ids` 是否真的存在于同版本的 `knowledge_cards` 里。**结果是评测集大量引用了不存在的卡片。**

| 版本 | 评测集条数 | 引用有效 | 引用失效 | 可用率 |
|---|---:|---:|---:|---:|
| `v0.2-seed` | 50 | 11 | **39** | **22.0%** |
| `v0.5-core` | 100 | 52 | **48** | **52.0%** |

按查询类型拆开看 `v0.5-core`，缺口分布非常清晰：

| 查询类型 | 总数 | 可命中 | 缺口 |
|---|---:|---:|---:|
| 能力等级证据 | 27 | 27 | 0 |
| 学习资源推荐 | 49 | 25 | **24** |
| 岗位匹配解释 | 15 | **0** | 15 |
| 趋势数据解读 | 5 | **0** | 5 |
| 隐私使用边界 | 4 | **0** | 4 |

缺失卡片按前缀：`KC-RES` 24 张、`KC-ROLE` 15 张、`KC-TREND` 5 张、`KC-ETHICS` 4 张。

**根因**：`knowledge_cards.csv` 实际只含两类（`skill_level` 300 + `learning_resource` 300），**完全没有 `role_skill` / `trend_interpretation` / `ethics_privacy` 三类卡片**。而评测集却引用了它们。

### 3.2 根因定位到生成器源码

`scripts/generate_dataset.mjs` 里，卡片数组是**一次性按类别顺序拼好的**：

```
knowledgeCards = [ skill_level 300 ] [ learning_resource ... ] [ role_skill 180 ] [ trend 60 ] [ ethics 60 ]
                  ↑ 顺序 1                 ↑ 顺序 2                ↑ 顺序 3          ↑ 顺序 4      ↑ 顺序 5
```

但写文件时按版本**从头部截断**：

```js
// 第 1497 行
knowledge_cards: knowledgeCards.slice(0, config.knowledge),
// v0.2-seed → slice(0, 200)  只留前 200 张 skill_level
// v0.5-core → slice(0, 600)  只留 300 skill + 300 resource
// v1.0-full → slice(0, 1200) 全部保留 ✓
```

而评测集 `retrievalEvaluation` 是从**完整的 1200 张数组**里抽的（第 1188 行 `knowledgeCards[(index * 37) % knowledgeCards.length]`），只把条数截断为 50/100。

**于是：截断后的卡片表 < 评测集引用的卡片范围 → 出现悬空引用。**

### 3.3 为什么自动验证没发现

`reports/validation_report.md` 显示 **451 项检查全过**。但 `validate_dataset.mjs` 对这两张表只查了：

- 行数与 manifest 一致
- 主键唯一
- 表头含公共元数据字段
- 元数据取值合法
- `data_split=test`

**没有"引用完整性"检查**（`retrieval_eval.expected_card_ids` 是否存在于 `knowledge_cards`）。所以缺陷漏网——**451 项全过 ≠ 数据可用**。

### 3.4 对你的影响与可行对策

**影响**：如果你用 `v0.5-core` 建库，100 条评测用例里有 48 条注定不可能通过——不是你的知识库建得不好，是标准答案指向了不存在的卡片。这份评测结果答辩时经不起追问。

**三条路，按推荐度排序：**

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. 用 `v1.0-full`** | 本地跑 `npm run generate` 生成完整包（1200 张卡片，5 类齐全） | **推荐**。v1.0-full 的切片刚好等于全量，评测集与卡片表自洽。仅体积大（约 90 MB，已被 `.gitignore` 忽略） |
| **B. 只评测可用的 52 条** | 用 `v0.5-core`，筛掉 48 条悬空用例，明确标注"评测集子集" | 可行但缩水，且回避了问题 |
| **C. 反馈给队友修生成器** | 建议把 `slice` 改成**按类别均衡抽样**，而非头部截断 | **最正确**，但依赖队友排期 |

**建议 A + C 并行**：先用 A 推进自己的工作，同时把缺陷反馈给队友。

## 四、建库方案（受平台约束推导）

### 4.1 硬约束

官方原文（`知识库/添加数据.md`）：

> + 文档型知识库仅支持关联**非结构化数据**，支持 **1 对 N**
> + 表格型知识库仅支持关联**结构化数据**，且仅支持 **1 对 1** 关联
> + 图片型知识库仅支持关联**图片（JPG/JPEG/PNG）**文件

**"表格型只能 1 对 1"直接决定：想按不同字段筛选，就必须拆成多个表格知识库。**

### 4.2 建议的库划分

| # | 知识库 | 类型 | 原料 | 靠什么筛选 |
|---|---|---|---|---|
| 1 | 职业与技能知识库 | **文档型** | `knowledge_cards.csv` 转 Markdown，按 category 分文件 | 文档属性 `category` / `claim_level` |
| 2 | 学习资源知识库 | **表格型** | `learning_resources.csv` 200 条 | `difficulty` / `estimated_hours` / `resource_type` |
| 3 | 岗位与技能要求知识库 | **表格型** | `job_skills.csv`（4491 行）单表 | `job_id` / `skill_id` / `required_score` |

> 若还要按城市/工作方式筛岗位，需再加一个 `jobs.csv` 表格库——**因为 `jobs` 与 `job_skills` 行数差异大且筛选维度不同，不能塞一张表，而百宝箱不给你写 SQL。**

### 4.3 上传前必须定好的事（改不了）

来自 `通过动态表单创建结构化知识库模板.md` 的警告：

| 规则 | 原文 |
|---|---|
| 表头格式 | 按 `字段名称\|字段描述` 维护，如 `name\|名称`；只写一个名称则字段名与描述都用该中文 |
| **字段名必须英文** | "若此知识库被卡片所消费，且此卡片需要在移动端展示，则**字段名称必须为英文**，否则卡片会展示异常" |
| 结构锁定 | "通过文件上传的方式创建的数据，在完成解析与录入后，**将无法再进行表结构的调整**" |
| 识别偏差 | 系统用**第一行数据**判断表结构与类型，"结果可能存在偏差，**建议进行二次确认**" |

**行动**：`jobs.csv` 有 30 个字段，其中大量是 `schema_version` / `origin` / `is_synthetic` / `generated_at` 这类治理字段。**上传前必须定好保留哪些**——传错要删库重建。

### 4.4 合规红线（团队已定，别踩）

| 红线 | 来源 |
|---|---|
| 展示 `jobs` / `trend_snapshots` 必须标注"演示数据" | README、DATA_CARD、TEAM_HANDOFF |
| `verified_course_metadata`(22条) 与 `public_catalog_topic_card`(98条) **不得合并标注为"官方课程"** | SOURCE_NOTES 原文 |
| `claim_level` 区分已核验/派生/模拟；`data_split=test` 只用于独立评测 | CHANGELOG 1.1.0、TEAM_HANDOFF |
| 不得用于真实录用/淘汰/薪酬/信贷决策 | DATA_CARD 禁止用途 |

**加分项**：把 `claim_level` / `data_split` / `is_market_fact` 做成文档知识库的**数据属性**，就能实现"只在已核验课程里检索"这类精确控制——正好呼应赛题的 AI 伦理设计要求。

### 4.5 检索参数（官方默认值，已核实）

| 配置项 | 默认值 | 出处 |
|---|---|---|
| 检索最大结果数 | `5` | 命中测试.md |
| 检索最小匹配度 | `0.500` | 命中测试.md |
| 精排最大结果数 | `3` | 命中测试.md |
| 精排最小匹配度 | `0.800` | 命中测试.md |
| 检索策略 | 智能检索 / 语义检索 / 关键词检索 | 命中测试.md |

> 注意：语义/全文检索 与 地理位置检索 **只能二选一，不能同时启用**。本项目用不上地理位置检索。
