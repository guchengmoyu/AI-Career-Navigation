# A02 数据库设计文档

## 一、设计概述

### 1.1 设计目标

- 支撑系统全部业务功能的数据存储需求
- 保障数据一致性、完整性和安全性
- 满足性能要求（查询响应 < 500ms）
- 支持未来业务扩展

### 1.2 数据库选型

| 数据库 | 类型 | 用途 | 选型理由 |
|--------|------|------|---------|
| MySQL 8.0 | 关系型 | 核心业务数据 | 成熟稳定，事务支持好 |
| Redis 7.x | 内存 KV | 缓存与会话 | 高性能，支持多种数据结构 |
| MongoDB 7.x | 文档型 | 半结构化数据 | 灵活 schema，适合存储 JSON |
| Neo4j 5.x | 图数据库 | 知识图谱 | 原生图存储，关系查询高效 |

### 1.3 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 数据库名 | snake_case | `ai_career_nav` |
| 表名 | snake_case，复数形式 | `users`、`career_profiles` |
| 字段名 | snake_case | `user_id`、`created_at` |
| 主键 | `id`，BIGINT 自增 | `id BIGINT AUTO_INCREMENT` |
| 外键 | `{关联表单数}_id` | `user_id`、`path_id` |
| 索引 | `idx_{表名}_{字段}` | `idx_users_email` |
| 时间字段 | `{动作}_at` | `created_at`、`updated_at` |
| 布尔字段 | `is_{状态}` | `is_active`、`is_deleted` |

### 2.2 表结构设计

#### 2.2.1 users 用户表

```sql
CREATE TABLE `users` (
  `id`              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `phone`           VARCHAR(20)     DEFAULT NULL COMMENT '手机号',
  `email`           VARCHAR(100)    DEFAULT NULL COMMENT '邮箱',
  `password_hash`   VARCHAR(255)    NOT NULL COMMENT '密码哈希',
  `nickname`        VARCHAR(50)     DEFAULT NULL COMMENT '昵称',
  `avatar_url`      VARCHAR(500)    DEFAULT NULL COMMENT '头像URL',
  `role`            VARCHAR(20)     NOT NULL DEFAULT 'user' COMMENT '角色: user/admin',
  `ai_style`        VARCHAR(20)     NOT NULL DEFAULT 'partner' COMMENT 'AI对话风格: mentor/partner/coach',
  `is_active`       TINYINT(1)      NOT NULL DEFAULT 1 COMMENT '是否启用',
  `is_deleted`      TINYINT(1)      NOT NULL DEFAULT 0 COMMENT '是否删除',
  `last_login_at`   DATETIME        DEFAULT NULL COMMENT '最后登录时间',
  `created_at`      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_users_phone` (`phone`),
  UNIQUE KEY `uk_users_email` (`email`),
  INDEX `idx_users_is_active` (`is_active`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

## 三、Redis 缓存设计

### 3.1 缓存 Key 规范

| Key 模式 | 数据类型 | TTL | 用途 |
|---------|---------|-----|------|
| `user:{id}:session` | String | 7 天 | 用户会话 Token |
| `user:{id}:profile` | Hash | 1 小时 | 用户画像缓存 |
| `user:{id}:path` | Hash | 30 分钟 | 当前路径缓存 |
| `user:{id}:chat:{convId}` | List | 24 小时 | 对话上下文 |
| `user:{id}:learning_today` | String | 当天 | 今日学习时长 |
| `system:hot_skills` | ZSet | 6 小时 | 热门技能排行 |
| `system:scenario:{type}` | String | 12 小时 | 场景配置缓存 |

### 3.2 缓存策略

```
读取流程: 先查 Redis → 命中返回 → 未命中查 MySQL → 写入 Redis → 返回
更新流程: 更新 MySQL → 删除 Redis 缓存 → 下次读取时重建
```

### 5.2 关系类型

```cypher
// 职业 -需要技能-> 技能
(j:Job)-[:REQUIRES {level: "required|preferred", min_score: 70}]->(s:Skill)

// 职业 -属于行业-> 行业
(j:Job)-[:BELONGS_TO]->(i:Industry)

// 技能 -学习路径-> 学习资源
(s:Skill)-[:LEARN_VIA {order: 1, effectiveness: 0.9}]->(r:Resource)

// 技能 -进阶到-> 技能
(s1:Skill)-[:ADVANCES_TO {gap_difficulty: "medium", hours: 80}]->(s2:Skill)

// 职业 -晋升到-> 职业
(j1:Job)-[:PROMOTES_TO {avg_years: 3, probability: 0.6}]->(j2:Job)

// 职业 -转行到-> 职业
(j1:Job)-[:TRANSFERS_TO {difficulty: "medium", transferable_skills: ["项目管理"]}]->(j2:Job)

// 技能 -相似于-> 技能
(s1:Skill)-[:SIMILAR_TO {similarity: 0.85}]->(s2:Skill)

// 学习资源 -覆盖技能-> 技能
(r:Resource)-[:COVERS {depth: "basic|intermediate|advanced"}]->(s:Skill)
```

### 5.3 示例查询

```cypher
// 查询目标职业所需技能
MATCH (j:Job {name: "AI 工程师"})-[r:REQUIRES]->(s:Skill)
RETURN s.name, r.level, r.min_score
ORDER BY r.min_score DESC

// 查询从当前职位到目标职位的晋升路径
MATCH path = shortestPath(
  (start:Job {name: "前端开发工程师"})-[:PROMOTES_TO|TRANSFERS_TO*..5]->(end:Job {name: "技术经理"})
)
RETURN path

// 查询某技能的完整学习路径
MATCH (s:Skill {name: "深度学习"})-[r:LEARN_VIA]->(res:Resource)
RETURN res.name, res.platform, res.rating, r.order
ORDER BY r.order
```

## 六、数据库安全设计

### 6.1 数据加密

| 数据类型 | 加密方式 | 说明 |
|---------|---------|------|
| 用户密码 | bcrypt 哈希 | 不可逆，加盐存储 |
| 手机号 | AES-256 加密 | 可逆，展示时脱敏 |
| 邮箱 | AES-256 加密 | 可逆，展示时脱敏 |
| 对话内容 | AES-256 加密 | 可逆，传输时 TLS |

### 6.2 数据备份策略

| 策略 | 频率 | 保留时间 | 说明 |
|------|------|---------|------|
| 全量备份 | 每天凌晨 2:00 | 30 天 | MySQL + MongoDB |
| 增量备份 | 每 6 小时 | 7 天 | MySQL binlog |
| Redis 持久化 | RDB + AOF | 实时 | 防止缓存数据丢失 |

### 6.3 数据脱敏规则

| 字段 | 脱敏方式 | 示例 |
|------|---------|------|
| 手机号 | 中间 4 位替换 | 138****5678 |
| 邮箱 | 用户名部分掩码 | z***@example.com |
| 姓名 | 保留姓氏 | 张** |
