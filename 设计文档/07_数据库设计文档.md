# A02 数据库设计文档

## 一、设计概述

### 1.1 设计目标

- 支撑系统核心业务功能的数据存储需求
- 保障数据一致性、完整性和安全性
- 满足性能要求（查询响应 < 500ms）
- 与百宝箱平台知识库协同，形成完整的数据架构

### 1.2 数据架构总览

本系统采用"百宝箱知识库 + MySQL 业务数据库"的双层数据架构：

| 数据层 | 存储方案 | 存储内容 | 说明 |
|--------|---------|---------|------|
| **知识层** | 百宝箱知识库 | 职业知识、学习资源、行业数据、认证信息 | 向量化存储，支持语义检索 |
| **业务层** | MySQL 8.0 | 用户数据、画像数据、路径数据、学习记录、场景会话 | 结构化存储，支持事务 |

**说明**：
- 百宝箱知识库替代了传统架构中的 Neo4j 图数据库和 MongoDB 文档数据库
- 百宝箱平台的对话管理能力替代了 Redis 缓存层（会话状态、对话上下文由平台管理）
- 仅保留 MySQL 存储业务状态数据

### 1.3 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 数据库名 | snake_case | `ai_career_nav` |
| 表名 | snake_case，复数形式 | `users`、`career_profiles` |
| 字段名 | snake_case | `user_id`、`created_at` |
| 主键 | `id`，BIGINT 自增 | `id BIGINT AUTO_INCREMENT` |
| 外键 | `{关联表单数}_id` | `user_id`、`path_id` |
| 索引 | `idx_{表名}_{字段}` | `idx_users_email` |
| 时间字段 | `{动作}_at` | `created_at`、`updated_at` |
| 布尔字段 | `is_{状态}` | `is_active`、`is_deleted` |

## 二、百宝箱知识库设计

### 2.1 知识库规划

| 知识库名称 | 类型 | 数据格式 | 数据内容 | 分段策略 |
|-----------|------|---------|---------|---------|
| 职业知识库 | 文档知识库 | Markdown/DOCX | 职业描述、技能要求、薪资范围、发展路径 | 智能分段，每段 500-2000 字 |
| 学习资源库 | 表格知识库 | CSV/XLSX | 课程、书籍、文章、视频等学习资源 | 按行分段 |
| 行业趋势库 | 文档知识库 | Markdown/PDF | 行业发展趋势、人才需求分析报告 | 智能分段 |
| 认证考试库 | 表格知识库 | CSV/XLSX | 职业认证信息、考试要求、认可度 | 按行分段 |

### 3.2 表结构设计

#### 3.2.1 users 用户表

```sql
CREATE TABLE `users` (
  `id`              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `phone`           VARCHAR(20)     DEFAULT NULL COMMENT '手机号',
  `email`           VARCHAR(100)    DEFAULT NULL COMMENT '邮箱',
  `password_hash`   VARCHAR(255)    NOT NULL COMMENT '密码哈希',
  `nickname`        VARCHAR(50)     DEFAULT NULL COMMENT '昵称',
  `avatar_url`      VARCHAR(500)    DEFAULT NULL COMMENT '头像URL',
  `role`            VARCHAR(20)     NOT NULL DEFAULT 'user' COMMENT '角色: user/admin',
  `ai_style`        VARCHAR(20)     NOT NULL DEFAULT 'partner' COMMENT 'AI对话风格: mentor/partner/coach',
  `is_active`       TINYINT(1)      NOT NULL DEFAULT 1 COMMENT '是否启用',
  `is_deleted`      TINYINT(1)      NOT NULL DEFAULT 0 COMMENT '是否删除',
  `last_login_at`   DATETIME        DEFAULT NULL COMMENT '最后登录时间',
  `created_at`      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_users_phone` (`phone`),
  UNIQUE KEY `uk_users_email` (`email`),
  INDEX `idx_users_is_active` (`is_active`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

## 四、数据库安全设计

### 4.1 数据加密

| 数据类型 | 加密方式 | 说明 |
|---------|---------|------|
| 用户密码 | bcrypt 哈希 | 不可逆，加盐存储 |
| 手机号 | AES-256 加密 | 可逆，展示时脱敏 |
| 邮箱 | AES-256 加密 | 可逆，展示时脱敏 |

### 4.2 数据备份策略

| 策略 | 频率 | 保留时间 | 说明 |
|------|------|---------|------|
| 全量备份 | 每天凌晨 2:00 | 30 天 | MySQL 全量备份 |
| 增量备份 | 每 6 小时 | 7 天 | MySQL binlog |

### 4.3 数据脱敏规则

| 字段 | 脱敏方式 | 示例 |
|------|---------|------|
| 手机号 | 中间 4 位替换 | 138****5678 |
| 邮箱 | 用户名部分掩码 | z***@example.com |
| 姓名 | 保留姓氏 | 张** |

## 五、与百宝箱平台的数据协同

### 5.1 数据分工

| 数据类型 | 存储位置 | 访问方式 | 说明 |
|---------|---------|---------|------|
| 用户业务数据 | MySQL | MCP 工具 API | 用户、画像、路径、记录等 |
| 职业/技能知识 | 百宝箱知识库 | 工作流知识库节点 | 向量化存储，语义检索 |
| 学习资源数据 | 百宝箱知识库 | 工作流知识库节点 | 表格型知识库 |
| 行业趋势数据 | 百宝箱知识库 | 工作流知识库节点 | 文档型知识库 |
| 对话上下文 | 百宝箱平台 | 平台自动管理 | 无需自建缓存 |
| 会话状态 | 百宝箱平台 | 平台自动管理 | 无需 Redis |

### 5.2 数据流转

