# A02 技术选型文档

## 一、技术选型概述

### 1.1 选型原则

| 原则 | 说明 |
|------|------|
| 平台优先 | 优先使用百宝箱平台提供的能力，减少自定义开发 |
| 成熟稳定 | 自定义部分优先选择经过生产验证的技术栈 |
| 团队熟悉 | 优先选择团队有经验的技术 |
| 成本可控 | 利用百宝箱平台资源，控制开发与运维成本 |
| 快速迭代 | 适合比赛项目的快速开发节奏 |

### 1.2 技术栈总览

```
┌──────────────────────────────────────────────────────┐
│                    平台层（百宝箱企业版）                │
│  智能体构建 + 知识库 + 工作流 + 插件 + 多端发布         │
│  大模型: 百灵 / 通义千问 / DeepSeek                    │
└──────────────────────────────────────────────────────┘
                           │
┌──────────────────────────────────────────────────────┐
│                    服务层（自定义 MCP 工具）             │
│  Node.js 18 + Express 4 + TypeScript 5 + Prisma 5    │
└──────────────────────────────────────────────────────┘
                           │
┌──────────────────────────────────────────────────────┐
│                    数据层                              │
│  MySQL 8.0（业务数据） + 百宝箱知识库（知识数据）       │
└──────────────────────────────────────────────────────┘
                           │
┌──────────────────────────────────────────────────────┐
│                    展示层（自定义前端）                  │
│  React 18 + TypeScript 5 + Ant Design 5 + ECharts 5  │
└──────────────────────────────────────────────────────┘
```

## 二、百宝箱平台能力选型

### 2.1 智能体构建模式

| 模式 | 说明 | 是否采用 |
|------|------|---------|
| AI 构建 | 自然语言驱动，AI 自动生成代码 | 否（需要更多自定义控制） |
| Agentic 自主规划 | 目标驱动，平台自主决策构建路径 | 否（需要精确控制流程） |
| 写 Prompt 创建 | 配置角色与指令，简单对话场景 | 辅助使用（简单对话场景） |
| **工作流创建** | **可视化拖拽编排业务逻辑** | **✅ 主要采用** |

**选择理由**：
- 工作流模式支持可视化编排，适合复杂的多步骤业务逻辑
- 可以精确控制知识库检索、MCP 工具调用、大模型处理的执行顺序
- 支持分支、循环、异常处理等控制流
- 支持版本管理和调试

### 2.2 大模型选择

| 对比项 | 通义千问 | 百灵大模型 | DeepSeek |
|--------|---------|-----------|---------|
| 中文能力 | 优秀 | 优秀 | 优秀 |
| 推理能力 | 强 | 强 | 强 |
| 百宝箱支持 | ✅ 原生 | ✅ 原生 | ✅ 支持 |
| Token 提供 | 平台提供 | 平台提供 | 平台提供 |
| 流式输出 | 支持 | 支持 | 支持 |
| Function Call | 支持 | 支持 | 支持 |

**选择策略**：
- **主力模型**：百灵大模型（百宝箱默认原生支持）
- **备选模型**：通义千问 / DeepSeek（通过平台切换）
- **降级策略**：工作流中配置异常分支，主力模型不可用时切换

### 2.3 知识库选型

| 知识库类型 | 数据格式 | 适用场景 | 本项目使用 |
|-----------|---------|---------|-----------|
| 文档知识库 | DOCX/PDF/TXT/MD | 非结构化文本检索 | ✅ 职业知识、行业趋势 |
| 表格知识库 | CSV/XLSX | 结构化数据查询 | ✅ 学习资源、认证信息 |
| 图片知识库 | JPG/PNG | 图像检索 | 否 |

**选择理由**：
- 文档知识库支持智能分段与摘要，适合存储职业描述、行业报告
- 表格知识库支持条件过滤和精确查询，适合学习资源、认证数据
- 百宝箱知识库提供语义检索 + 重排序能力，替代传统知识图谱方案

### 2.4 工作流节点使用计划

| 节点类型 | 使用场景 | 说明 |
|---------|---------|------|
| 开始/结束节点 | 所有工作流 | 接收输入、输出结果 |
| 文本大模型节点 | 画像分析、路径优化、评估报告 | 调用大模型进行推理 |
| 知识库节点 | 职业查询、资源匹配、行业分析 | 语义检索知识库 |
| MCP 插件节点 | 画像计算、路径生成、场景管理 | 调用自定义业务逻辑 |
| 意图识别节点 | 对话路由 | 识别用户意图，分发到对应流程 |
| 分支节点 | 条件判断 | 根据条件选择不同处理路径 |
| 代码节点 | 数据格式化、后处理 | JavaScript/Python 脚本处理 |
| 变量节点 | 状态管理 | 传递中间结果 |
| 直接回复节点 | 结果输出 | 向用户返回处理结果 |

## 三、自定义服务技术选型

### 3.1 运行时：Node.js 18

| 对比项 | Node.js 18 | Python 3.11 | Java 21 |
|--------|-----------|------------|---------|
| 开发效率 | 高 | 高 | 中 |
| 前后端统一 | ✅ TypeScript | ❌ 需切换语言 | ❌ 需切换语言 |
| 异步性能 | 优秀 | 一般 | 优秀 |
| 部署复杂度 | 低 | 低 | 高 |

**选择理由**：
- 与前端统一 TypeScript 技术栈，降低团队学习成本
- MCP 工具服务逻辑相对简单，Node.js 完全胜任
- 部署简单，适合比赛项目快速迭代

### 3.2 Web 框架：Express 4

**选择理由**：
- 学习成本最低，开发速度快
- 中间件生态最丰富
- 满足 MCP 工具服务的性能需求

### 3.3 ORM 框架：Prisma 5

**选择理由**：
- 自动生成 TypeScript 类型，类型安全最佳
- Schema 声明式定义，迁移管理方便
- Prisma Studio 可视化数据管理

### 3.4 其他服务端依赖

| 库 | 版本 | 用途 |
|----|------|------|
| jsonwebtoken | 9.x | JWT 认证（前端 API） |
| bcryptjs | 2.x | 密码加密 |
| cors | 2.x | 跨域处理 |
| helmet | 7.x | 安全头设置 |

## 四、数据库选型

### 4.1 MySQL 8.0（唯一自建数据库）

| 对比项 | MySQL 8.0 | PostgreSQL 16 |
|--------|----------|-------------|
| 事务支持 | 优秀 | 优秀 |
| 运维成本 | 低 | 中 |
| 生态工具 | 最丰富 | 丰富 |
| 云服务支持 | 广泛（阿里云 RDS） | 广泛 |

**选择理由**：
- 成熟稳定，运维成本低
- 适合结构化业务数据存储
- 阿里云 RDS 托管服务，降低运维压力
- 仅存储业务状态数据（用户、画像、路径、记录），知识数据由百宝箱知识库存储

### 4.2 不再需要的数据库

| 数据库 | 传统方案用途 | 百宝箱替代方案 |
|--------|------------|-------------|
| ~~Redis~~ | 会话缓存、对话上下文 | 百宝箱平台自动管理对话状态 |
| ~~MongoDB~~ | 学习资源、行业报告存储 | 百宝箱文档/表格知识库 |
| ~~Neo4j~~ | 职业知识图谱 | 百宝箱知识库语义检索 |

## 五、前端技术选型

### 5.1 前端框架：React 18

**选择理由**：
- 团队成员均有 React 开发经验
- React 生态最丰富，ECharts、Ant Design 等库支持好
- React 18 的并发特性适合流式 AI 对话场景
- TypeScript 深度集成，提升代码质量

### 5.2 UI 组件库：Ant Design 5

**选择理由**：
- 组件丰富，开箱即用，适合快速开发
- 表单、表格等企业级组件成熟
- Design Token 主题定制，满足设计需求

### 5.3 图表可视化：ECharts 5

**选择理由**：
- 原生支持雷达图，是本项目核心可视化需求
- 图表类型丰富（折线图、柱状图、仪表盘、热力图等）
- 支持大数据量渲染

### 5.4 状态管理：Zustand

**选择理由**：
- API 极简，代码量最少
- 适合中小型应用
- TypeScript 友好

### 5.5 其他前端依赖

| 库 | 版本 | 用途 |
|----|------|------|
| React Router | 6.x | 路由管理 |
| Axios | 1.x | HTTP 请求（调用自定义前端 API） |
| Day.js | 1.x | 日期处理 |
| React Markdown | 9.x | Markdown 渲染 |
| Framer Motion | 11.x | 动画效果 |

## 六、与百宝箱平台的能力对比

### 6.1 平台提供 vs 自定义开发

| 能力 | 百宝箱平台提供 | 自定义开发 | 说明 |
|------|-------------|-----------|------|
| 大模型调用 | ✅ | ❌ | 平台原生支持，Token 由平台提供 |
| 对话管理 | ✅ | ❌ | 多轮对话、上下文维护由平台处理 |
| 意图识别 | ✅ | ❌ | 工作流内置意图识别节点 |
| 知识检索 | ✅ | ❌ | 知识库模块提供语义检索 |
| 流程编排 | ✅ | ❌ | 可视化工作流编排 |
| 多端发布 | ✅ | ❌ | Web/H5/小程序一键发布 |
| 用户认证 | ✅ | ❌ | 平台内置用户管理 |
| 职业画像计算 | ❌ | ✅ | MCP 工具：自定义评分算法 |
| 路径生成算法 | ❌ | ✅ | MCP 工具：能力差距分析 |
| 场景评估引擎 | ❌ | ✅ | MCP 工具：多维度评估 |
| 数据可视化 | ❌ | ✅ | React + ECharts 自定义页面 |
| 业务数据存储 | ❌ | ✅ | MySQL 业务数据库 |

### 6.2 架构简化收益

| 指标 | 传统架构 | 百宝箱架构 | 简化比例 |
|------|---------|-----------|---------|
| 数据库数量 | 4 个（MySQL+Redis+MongoDB+Neo4j） | 1 个（MySQL）+ 知识库 | 75% |
| 后端 API 数量 | 30+ 个 RESTful 接口 | 10 个 MCP 工具 + 少量前端 API | 60%+ |
| 部署组件 | 前端+后端+4个数据库+缓存 | 前端+MCP服务+MySQL（平台托管智能体） | 50%+ |
| AI 集成工作量 | 自建 LLM 调用、Prompt 管理、对话引擎 | 平台配置 | 80%+ |
| 开发周期 | 8-10 周 | 6-8 周 | 20-30% |

## 七、部署与运维选型

### 7.1 部署方案

| 组件 | 部署方式 | 说明 |
|------|---------|------|
| 百宝箱智能体 | 百宝箱平台托管 | 无需自建部署 |
| 百宝箱知识库 | 百宝箱平台托管 | 无需自建部署 |
| MCP 工具服务 | 云服务器 / Docker 容器 | 对接百宝箱 MCP 协议 |
| MySQL | 阿里云 RDS | 托管服务，降低运维 |
| 自定义前端 | CDN + Nginx | 静态资源加速 |

### 7.2 CI/CD 流程

```
代码提交 (Git)
    → 自动化测试 (Jest)
      → 构建 (Docker Build)
        → 部署 MCP 工具服务
          → 百宝箱平台配置更新
            → 健康检查
```
