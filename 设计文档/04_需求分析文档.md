# A02 需求分析文档

## 一、项目背景分析

### 1.1 赛题背景

在全球技术变革加速、职业形态快速迭代的背景下，传统的职业规划与技能培训模式已难以满足个体应对不确定未来的需要。AI 不再仅是效率工具，更应成为陪伴个体成长的"认知伙伴"。

本赛题要求基于**蚂蚁百宝箱企业版**平台，构建一个以大模型为内核的 AI 职业导航系统，帮助用户实现从"被动就业"到"主动成长"的转变。

### 1.2 核心问题域

| 问题域 | 现状痛点 | 目标期望 |
|--------|---------|---------|
| 职业规划 | 缺乏数据支撑，主观判断为主 | AI 驱动的动态职业画像与路径规划 |
| 技能提升 | 学习资源零散，缺乏系统性 | 个性化学习路径与资源推荐 |
| 职场准备 | 缺少实践场景，经验积累慢 | 沉浸式职场场景模拟训练 |
| 成长追踪 | 成果难以量化，缺乏反馈 | 可视化成长轨迹与智能反馈 |
| 信息孤岛 | 教育、招聘、认证数据割裂 | 多源数据整合与生态打通 |

### 1.3 技术闭环要求

赛题要求严格体现六大技术闭环：

```
感知（用户状态采集 — 百宝箱对话交互 + 前端问卷）
  → 认知（职业趋势分析 — 知识库检索 + 大模型分析）
    → 决策（路径规划 — MCP 工具 + 工作流编排）
      → 生成（学习内容与建议 — 大模型生成 + 知识库匹配）
        → 执行（任务提醒与资源对接 — MCP 工具 + 工作流自动化）
          → 反馈（效果评估与动态调整 — MCP 工具评估 + 画像更新）
```

## 二、业务需求分析

### 2.1 业务目标

| 目标类别 | 具体目标 | 可量化指标 |
|---------|---------|-----------|
| 平台适配 | 完成蚂蚁百宝箱企业版平台适配 | 智能体正常调用运行 |
| 多端发布 | Web + 支付宝小程序 | 至少 Web 端必选上线 |
| 核心功能 | 职业画像 + 路径规划 + 场景模拟 | 至少 3 个场景模块 |
| 用户体验 | 自然语言交互 + 可视化展示 | 用户满意度 > 80% |
| 合规安全 | 数据隐私保护 + AI 伦理 | 符合个人信息安全规范 |

### 2.2 业务流程分析

#### 2.2.1 用户注册与初始化流程

```
用户访问系统（百宝箱 Web/H5/小程序入口）
    → 注册/登录（百宝箱平台用户认证）
      → 填写基础信息问卷（百宝箱对话交互 or 自定义前端页面）
        → 触发画像生成工作流
          → MCP 工具计算能力评分 + 知识库检索岗位要求 + 大模型综合分析
            → 生成初始职业画像
              → 进入系统主界面
```

#### 2.2.2 职业画像生成流程

```
用户录入个人信息（教育背景、技能、兴趣、经历）
    → 百宝箱工作流触发
      → MCP 工具：解析用户数据，计算多维度能力评分
        → 百宝箱知识库：检索目标岗位技能要求与行业数据
          → 大模型：综合分析，生成深度画像报告
            → 生成多维度能力雷达图
              → 用户确认/调整画像
```

#### 2.2.3 学习路径生成流程

```
用户设定职业目标
    → 百宝箱工作流触发
      → MCP 工具：分析当前能力与目标差距
        → 百宝箱知识库：检索学习路径推荐与资源匹配
          → MCP 工具：生成分阶段学习计划
            → 大模型：优化路径与时间安排
              → 生成分阶段学习计划
                → 用户确认路径
                  → 开始学习 → 进度追踪 → 动态调整
```

#### 2.2.4 场景模拟训练流程

```
用户选择训练场景
    → 百宝箱工作流触发
      → MCP 工具：初始化场景与角色配置
        → 用户与 AI 角色进行对话交互（百宝箱智能体对话）
          → 百宝箱工作流：实时记录交互数据
            → 交互结束触发评估工作流
              → MCP 工具：评估用户表现
                → 大模型：生成评估报告与改进建议
                  → 推荐相关学习资源（知识库检索）
```

### 2.3 业务规则

| 编号 | 规则描述 | 优先级 | 实现方式 |
|------|---------|--------|---------|
| BR-01 | 用户个人信息采集需获得明确授权 | 高 | 百宝箱对话引导 + 前端确认 |
| BR-02 | 职业路径需支持多轮调整与细化 | 高 | MCP 工具 + 工作流重新触发 |
| BR-03 | AI 回复需标注置信度与参考依据 | 中 | 百宝箱智能体指令配置 |
| BR-04 | 学习资源推荐需考虑用户学习偏好 | 中 | 知识库检索 + 大模型个性化 |
| BR-05 | 场景模拟需支持多种难度级别 | 中 | MCP 工具参数化配置 |
| BR-06 | 敏感数据存储需加密处理 | 高 | MCP 工具层数据加密 |
| BR-07 | AI 建议需避免算法偏见 | 高 | 百宝箱智能体指令约束 |
| BR-08 | 系统需设置使用时长提醒，防止过度依赖 | 中 | MCP 工具 + 工作流定时提醒 |

## 三、用户需求分析

### 3.1 用户角色定义

| 角色 | 描述 | 核心需求 |
|------|------|---------|
| 高校学生 | 大学生，即将步入职场 | 职业方向探索、技能储备、实习/就业准备 |
| 职场新人 | 工作 1-3 年 | 职业定位、技能提升、晋升路径规划 |
| 职业转型者 | 希望转行的从业者 | 转行路径规划、新技能学习、行业分析 |
| 终身学习者 | 持续自我提升 | 能力持续迭代、学习资源推荐、成长追踪 |

### 3.2 核心用户需求

#### 需求 1：了解自身职业竞争力
- **用户故事**：作为用户，我希望系统能根据我的信息生成能力雷达图，让我清楚自己的优势和短板
- **验收标准**：支持 5 维以上能力评估，可视化雷达图展示
- **实现方式**：百宝箱工作流（MCP 工具计算 + 大模型分析）+ 自定义前端雷达图页面

#### 需求 2：获得个性化职业路径
- **用户故事**：作为用户，我希望输入目标职位后，系统能为我生成 3-5 年的可执行学习路径
- **验收标准**：路径包含阶段性目标、具体学习任务、时间安排
- **实现方式**：百宝箱工作流（MCP 路径生成 + 知识库资源匹配 + 大模型优化）

#### 需求 3：模拟真实职场场景
- **用户故事**：作为用户，我希望通过模拟职场场景来锻炼实际工作能力
- **验收标准**：至少 3 种场景，交互式对话，有评估与反馈
- **实现方式**：百宝箱智能体对话 + MCP 场景管理工具 + 工作流评估流程

#### 需求 4：追踪学习进度
- **用户故事**：作为用户，我希望看到自己的学习进度和成长轨迹
- **验收标准**：可视化进度面板，支持里程碑标记
- **实现方式**：MCP 进度查询工具 + 自定义前端可视化页面

#### 需求 5：获得 AI 陪伴与激励
- **用户故事**：作为用户，我希望 AI 能定期提醒我的学习计划并给予鼓励
- **验收标准**：支持多种对话风格，定期回顾机制
- **实现方式**：百宝箱智能体多角色配置 + MCP 进度追踪工具

#### 需求 6：连接外部资源
- **用户故事**：作为用户，我希望系统能推荐课程、岗位、认证等外部资源
- **验收标准**：对接至少 1 个外部学习/招聘平台 API
- **实现方式**：百宝箱知识库存储资源数据 + MCP 工具对接外部 API

## 四、非功能需求分析

### 4.1 性能需求

| 指标 | 要求 | 说明 |
|------|------|------|
| 页面加载时间 | < 3 秒 | 自定义前端页面首屏加载 |
| 大模型响应时间 | < 10 秒 | 百宝箱平台大模型推理 |
| MCP 工具响应 | < 5 秒 | 自定义工具业务计算 |
| 知识库检索 | < 2 秒 | 百宝箱知识库语义检索 |

### 4.2 安全需求

| 需求 | 说明 |
|------|------|
| 传输安全 | 百宝箱平台全站 HTTPS，API 通信加密 |
| 存储安全 | 敏感数据 AES-256 加密（MCP 工具层实现） |
| 认证授权 | 百宝箱平台用户认证 + MCP 工具鉴权 |
| 数据脱敏 | MCP 工具中实现敏感信息脱敏 |
| 最小必要 | 仅采集业务必需的用户数据 |

### 4.3 兼容性需求

| 平台 | 要求 |
|------|------|
| Web 浏览器 | Chrome、Firefox、Safari、Edge 最新两个版本 |
| 移动端 | iOS Safari、Android Chrome |
| 屏幕适配 | 响应式设计，支持 375px - 1920px 宽度 |
| 小程序 | 支付宝小程序（必选）、微信小程序（可选） |

### 4.4 AI 伦理需求

| 伦理维度 | 要求 | 实现方式 |
|---------|------|---------|
| 算法公平 | 职业推荐不因性别、年龄、学历产生歧视 | 百宝箱智能体指令约束 |
| 透明性 | AI 决策依据可解释、可追溯 | 大模型回复附带推理依据 |
| 隐私保护 | 遵循 GDPR 及《个人信息保护法》 | MCP 工具层数据加密与脱敏 |
| 防过度依赖 | 设置使用时长提醒，鼓励自主决策 | MCP 工具定时提醒 |
| 内容安全 | AI 输出内容经过安全过滤 | 百宝箱平台内置安全过滤 |

## 五、竞品分析

### 5.1 市场现有产品

| 产品 | 类型 | 优势 | 不足 |
|------|------|------|------|
| LinkedIn Learning | 学习平台 | 海量课程资源 | 缺乏个性化路径规划 |
| 领英职场 | 职业社交 | 职位推荐精准 | 学习功能薄弱 |
| BOSS 直聘 | 招聘平台 | 岗位丰富 | 缺少成长陪伴 |
| 知乎/脉脉 | 社区平台 | UGC 内容丰富 | 缺乏系统化规划 |
| 前程无忧 | 传统招聘 | 行业数据丰富 | 交互体验传统 |

### 5.2 差异化竞争点

| 差异点 | 说明 |
|--------|------|
| AI 深度融合 | 以大模型为内核，非简单规则推荐 |
| 全流程闭环 | 感知→认知→决策→生成→执行→反馈 |
| 场景化训练 | 沉浸式职场模拟，非纯理论学习 |
| 长期陪伴 | 不是一次性工具，具备成长追踪与激励 |
| 平台生态 | 依托蚂蚁百宝箱，多端触达，低成本部署 |

## 七、约束条件与假设

### 7.1 约束条件

1. **平台约束**：必须基于蚂蚁百宝箱企业版开发，利用平台提供的知识库、工作流、插件等能力
2. **时间约束**：开发周期 6-8 周
3. **资源约束**：3-4 人团队，百宝箱平台提供大模型 Token 资源
4. **合规约束**：符合《个人信息保护法》及相关法规
5. **技术约束**：使用百宝箱支持的大模型（百灵、通义千问、DeepSeek）

### 7.2 假设条件

1. 蚂蚁百宝箱企业版提供稳定的 API 和技术支持
2. 百宝箱知识库、工作流、MCP 插件功能满足业务需求
3. 团队成员具备基本的前端开发和百宝箱平台使用能力
4. 公开行业数据可用于知识库构建
5. 大模型 Token 由百宝箱平台提供
