本文将介绍卡片的核心概念及其在百宝箱平台中的使用价值，帮助开发者快速理解卡片能力并选择合适的创建方式。

## 什么是卡片
卡片是智能体应用中用于向用户呈现结构化信息与交互操作的可复用交互单元。它既可以展示图文内容（如商品介绍、服务指南），也可以承载交互行为（如按钮点击、跳转链接、拨打电话等），广泛应用于对话开场白、工作流回复节点、插件展位等场景。

在平台中，卡片将以标准化组件的形式存在，支持在不同终端上按需渲染，实现“一次搭建，多端分发”。

## 核心特性
平台围绕“高效构建、灵活集成、多端一致”的目标，提供三大核心能力：

### 多端自适应的卡片类型
为适配不同发布环境，平台抽象出统一的卡片木星，并自动映射到以下渠道：

+ H5 卡片：适用于 Web 浏览器、App 内嵌 WebView、PC 网页等;
+ 小程序卡片：兼容支付宝与微信小程序，需配合平台官方在宿主小程序平台发布的模板进行使用；
+ Cube 卡片：专用于百宝箱内部场景（外部开发者无需关注）。

:::info
💡 **说明**：卡片类型在创建时选定，将决定其开发方式与可投放渠道，请根据业务目标按需选择。

:::

### 三种灵活的创建方式
无论您是产品、运营还是有代码基础的开发者，均可选择最适合的生产路径：

+ AI 生成：输入自然语言（如“生成一个热门景点推荐卡片”），AI 自动产出服务平台设计规范、支持点击事件（跳转、拨号、导航等）的可交互初稿，并附带变量使用说明。
+ 低代码搭建：通过可是话编辑器拖拽文本、图片、按钮等组件，绑定动态变量，所见即所得，支持官方模板一键复用。
+ 代码导入：开发者将已有 React 组件打包为 UMD 模块并部署至 CDN，平台通过 URL 引入，满足光定制或性能敏感场景需求。

### 统一管理与高效协同
+ 版本控制与回溯：修改可追溯，支持在版本管理中进行快速回滚。
+ 无缝关联智能体：可嵌入智能体的开场白、工作流节点或插件展位。
+ 一键式多端投放：关联智能体应用够随之发布至 H5、支付宝/微信小程序，终端将自动渲染。

## 整体使用链路说明
百宝箱卡片采用“创建 -> 关联 -> 投放”的三段式链路，帮助开发者高效构建并交付对应的卡片内容。该链路覆盖从卡片构建到对客使用的完整生命周期，具体如下：

### 步骤 1： 创建卡片
开发者任选一种方式进行卡片构建，详细说明请参见：

+ 低代码搭建：[通过低代码可视化搭建](https://alipaytbox.yuque.com/sxs0ba/huntb8/akz2dkrnbdxgw6bk)。
+ 代码导入：[通过代码导入创建](https://alipaytbox.yuque.com/sxs0ba/huntb8/ux41wx5q3zlfnmdv)。
+ AI 生成：[使用 AI 生成卡片](https://alipaytbox.yuque.com/sxs0ba/huntb8/card_ai_overview)。

### 步骤 2： 关联智能体应用
开发者将已创建且推进至已发布桩体的卡片嵌入智能体应用的指定节点（如开场白、工作流回复、插件展位），并通过参数映射将应用上下文数据传入卡片，实现动态渲染，详细说明可参见：[关联卡片](https://alipaytbox.yuque.com/sxs0ba/huntb8/card_binging)。

### 步骤 3：渠道投放
在发布应用并上架到目标渠道时，卡片将随之进行投放，用户可在对应的终端进行使用。详细说明可参见：[应用发布](https://alipaytbox.yuque.com/sxs0ba/huntb8/agent_release)。
