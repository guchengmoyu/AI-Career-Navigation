> 本文面向接入智能体微信小程序插件的宿主开发者，介绍如何开启插件页面的“发送给朋友”能力。
>

写在前面：智能体插件**暂不提供**直接分享智能体页面的功能，原因是智能体链接上携带用户身份信息，A分享给B后，B会以A的身份进入页面，会共享会话。

## 一、方案说明
配置宿主落地页。点击“分享给朋友”后，跳转到宿主落地页，由宿主落地页去承接获取用户登录态，跳转到智能体页面。

![](https://intranetproxy.alipay.com/skylark/lark/__mermaid_v3/4bad538cf1d2858f96a854ac9d29a8c9.svg)

## 二、接入前准备
开始接入前，请确认：

1. 宿主已经按照插件接入文档配置插件及 `exportToPlugin.js`。
2. 宿主准备了一个已经注册在 app.json 中的页面作为分享落地页（落地页可以是专门的中间页，也可以复用宿主现有首页）。
3. 该落地页能够获取当前访问者的 user_id，或能够生成当前访问者的一次性登录 code。
4. 如果插件位于分包中，落地页也能够正常跳转到对应插件页面。

## 三、开启分享功能
### 1. 导出分享配置
在宿主的 `exportToPlugin.js` 中增加 `getChatPluginShareConfig`：

```javascript
module.exports = {
  getWXGlobalObject: () => {
    return wx;
  },

  getChatPluginShareConfig: () => {
    return {
      entryPath: '/pages/chat-share/index', // 必填，分享页面
      title: '和你分享一个智能体',  // 可选，分享卡片的标题
      // imageUrl: 'https://example.com/share-cover.jpg', // 可选，分享卡片的图片
    };
  },
};
```



配置字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| entryPath | string | 是 | 宿主分享落地页的绝对路径，以 / 开头，不能包含 query 或 hash |
| title | string | 否 | 分享卡片标题；不传时使用小程序默认标题 |
| imageUrl | string | 否 | 分享卡片图片地址 |
| version | number | 否 | 适配器协议版本，默认且当前仅支持 1 |
| enabled | boolean | 否 | 分享开关，默认 true；显式传 false 时关闭分享 |
| params | object | 否 | 页面参数 |


以下是最简配置：

```javascript
getChatPluginShareConfig: () => ({
  entryPath: '/pages/chat-share/index',
});
```

如需临时关闭线上分享，可以保留配置并设置：

```javascript
getChatPluginShareConfig: () => ({
  entryPath: '/pages/chat-share/index',
  enabled: false,
});
```

### 2. 注册宿主落地页
确保 entryPath 对应页面已经在 app.json 中注册，例如：

```json
{
  "pages": [
    "pages/index/index",
    "pages/chat-share/index"
  ]
}
```

entryPath 必须写为：

```latex
/pages/chat-share/index
```

不要在 entryPath 中预先拼接 query，需要追加页面参数请在`params`中添加：

```latex
/pages/chat-share/index?foo=bar
```

插件分享时会自动追加以下公开参数：

```latex
/pages/chat-share/index?from=chat_plugin_share&agent_id=xxx&channel=xxx
```

其中：

+ from 用于区分普通启动和插件分享启动。
+ agent_id 表示好友需要打开的智能体。
+ channel 表示双方约定的接入渠道，未配置时可能不传。

## 四、实现宿主落地页
落地页需要识别分享来源，获取当前打开卡片的用户身份，然后重新拼装插件 URL。

```javascript
Page({
  async onLoad(options) {
    if (options.from !== 'chat_plugin_share') {
      return;
    }

    try {
      // 由宿主按现有登录链路实现。
      // 返回当前访问者自己的 code 或 userId。
      const auth = await getCurrentUserAuth();

      const query = [
        'agent_id=' + encodeURIComponent(options.agent_id),
        'entrance=share',
      ];

      if (options.channel) {
        query.push('channel=' + encodeURIComponent(options.channel));
      }

      if (auth.code) {
        query.push('code=' + encodeURIComponent(auth.code));
      } else if (auth.userId) {
        query.push('user_id=' + encodeURIComponent(auth.userId));
      } else {
        throw new Error('当前访问者尚未登录');
      }

      // 跳转智能体页面
      wx.navigateTo({
        url: 'plugin://chatPlugin/chat-page?' + query.join('&'),
      });
      
    } catch (error) {
      console.error('打开智能体失败', error);
      wx.showToast({
        title: '请登录后重试',
        icon: 'none',
      });
    }
  },
});
```

getCurrentUserAuth() 需要由宿主根据自身登录体系实现：

+ 使用 user_id 模式时，返回当前访问者自己的稳定用户标识。
+ 使用 code + channel 模式时，生成当前访问者自己的一次性登录 code。
+ 不得读取或复用分享者的 user_id、code、Session 或聊天会话信息。

## 五、复用宿主首页
如果不希望新增中间页，可以直接将宿主首页配置为 entryPath：

```javascript
getChatPluginShareConfig: () => ({
  entryPath: '/pages/index/index',
});
```

然后在首页 onLoad 中识别 options.from：

```javascript
Page({
  onLoad(options) {
    if (options.from === 'chat_plugin_share') {
      this.openSharedAgent(options);
      return;
    }

    // 原有首页启动逻辑
  },

  async openSharedAgent(options) {
    // 获取当前访问者身份并跳转插件，处理方式同上一节。
  },
});
```

## 六、发布前验收
建议使用两个不同微信账号完成真机验证：

1. 账号 A 从宿主进入插件页，确认右上角可以选择“发送给朋友”。
2. 账号 A 将卡片发送给账号 B。
3. 账号 B 打开卡片，确认先进入配置的宿主落地页，再自动打开同一个智能体。
4. 确认账号 B 使用的是自己的登录身份，而不是账号 A 的身份。
5. 检查分享路径，确认不包含 user_id、登录 code、Session 和会话 ID。
6. 将 enabled 设置为 false，确认插件分享入口关闭。
7. 删除 getChatPluginShareConfig，确认插件其他功能仍可正常使用。

## 七、常见问题
### 1. version 和 enabled 必须传吗？
不需要。传入合法 entryPath 就会默认开启分享：

+ version 不传时按 1 处理。
+ enabled 不传时按 true 处理。
+ enabled 显式传 false 时关闭分享。
+ version 显式传入当前不支持的值时关闭分享。

### 2. 宿主没有实现分享适配器会怎样？
插件页面仍然可以正常使用，但不会开放“发送给朋友”入口，不影响旧宿主继续使用插件。

### 4. 为什么配置后仍显示“当前页面不可转发”？
请依次检查：

1. getChatPluginShareConfig 是否通过宿主的 exportToPlugin.js 正确导出。
2. entryPath 是否以 / 开头，且不包含 query、hash、协议或相对路径。
3. entryPath 是否已在宿主 app.json 的 pages 或 subpackages 中注册。
4. 是否显式配置了 enabled: false。
5. 是否传入了当前不支持的 version。
6. 是否已使用包含分享适配器能力的插件版本重新构建并真机预览。

### 5. 可以直接把 user_id 放进分享链接吗？
不可以。分享链接会发送给其他用户，透传分享者身份可能导致账号串用、数据越权或会话泄露。用户身份必须由宿主落地页针对当前访问者重新获取。
