## Agentic 自主规划构建是什么
**Agentic 自主规划模式**则是一种**目标驱动**的构建方式。在该方式下，开发者只需定义智能体的能力边界（可调用的工具、知识库、子智能体），而**执行路径由 AI 在运行时自主决定**。智能体根据用户输入的目标，自主完成分析任务 → 制定执行计划 → 选择工具 → 根据中间结果动态调整策略 → 交付最终成果。

## 与工作流编排方式的区别
**工作流（Workflow）模式**是一种"预定义路径"的构建方式。使用工作流编排方式，开发者在搭建阶段就确定好节点的执行顺序、分支条件和数据流向。智能体运行时严格按照预设的 DAG（有向无环图）逐步执行，不具备自主决策能力。它适合**流程固定、路径可穷举**的确定性任务。

### 与工作流编排方式的核心差异
| 维度 | 工作流（Workflow）编排 | Agentic 自主规划 |
| --- | --- | --- |
| 执行路径 | 搭建时预定义，运行时固定 | 运行时由 AI 自主决定，动态调整 |
| 适用任务 | 流程固定、路径可穷举的确定性任务 | 目标明确但路径不确定的探索性任务 |
| 工具调用 | 按预设顺序依次调用 | AI 根据当前状态自主选择调用哪个工具 |
| 分支决策 | 开发者用条件节点预设所有分支 | AI 实时判断下一步做什么 |
| 错误恢复 | 走到预设的异常分支或终止 | AI 自主诊断错误原因，调整策略继续 |
| 多轮交互 | 每次请求独立执行一遍 DAG | 在同一会话中持续推理，跨轮次保持状态 |
| 构建门槛 | 需要穷举所有可能路径 | 只需定义能力边界，AI 自主组合 |
| 典型场景 | 固定审批流、模板化报告生成 | 数据分析、复杂咨询、多步骤调研 |


### 实际任务场景下的对比
| 任务 | 工作流编排 | Agentic 自主规划 |
| --- | --- | --- |
| 帮我分析上月华东区域的销售异常，给出原因和改进建议。 | 开发者需要预先设计好"查询销售数据 → 计算同比环比 → 判断是否异常 → 生成报告"的固定流程。如果分析过程中发现需要额外查看某个门店的库存数据，但这条路径没有预设——流程就卡住了。 | 智能体接到目标后，自主制定分析计划 → 先查询整体数据 → 发现某门店异常 → 自主决定深入查询该门店的库存和人员数据 → 发现是断货导致 → 综合生成包含根因分析和改进建议的报告。**整个过程无需预设路径，AI 根据中间结果动态决策下一步**。 |


## 为什么企业需要平台化的自主规划能力
### 行业背景：Harness Engineering 理念兴起
过去一年，OpenClaw、Hermes、Claude Code 等智能体产品掀起了一波热潮，也带火了它们背后的 **Harness Engineering 理念**——用结构化的工作区、上下文管理与工具约定，替代"每次对话各自为战"的原始使用方式。越来越多的团队开始把这套思路搬进自己的 Agent 开发中。

然而，真正动手落地的人往往会发现：**这条路走到"企业级"就开始卡壳**。

### 企业自建智能体的五大障碍
我们梳理了企业在自建 Agentic 智能体时最常遇到的五个核心挑战：

**1. 多用户、多副本，状态怎么管理？**

个人助手型 Agent 用一个本地目录做工作区，单机单用户完全没问题。但企业服务要对外开放，多个用户的工作空间要隔离，Agent 水平扩容到多台机器后，同一用户的会话状态又要在副本间共享——本地存储的假设直接崩掉了。

**2. 工具执行怎么保证安全隔离？**

Agent 调用 Shell 或运行用户驱动的脚本，放在本地可信开发机上无所谓，一旦上线服务，把任意用户输入的命令直接在宿主机上执行就是严重的安全漏洞。沙箱和权限边界不是"可选的优化"，而是"上线的前提"。

**3. 上下文压缩和分层记忆谁来实现？**

Harness Engineering 把上下文管理讲得很清楚，但真正做起来细节非常多：压缩时机、压缩策略、压缩前的事实提取、历史的可检索性、跨进程重启后的恢复……大多数开源框架只给了 short/long memory 的抽象接口，具体实现还是要企业自己来。

**4. Multi-Agent 编排怎么做才对？**

子任务分发、上下文隔离、异步执行、结果回收、超时取消——每一项单独做都不难，但要拼成一个可管理的编排层，代码复杂度会快速上升。工程上的"怎么声明子 Agent、什么时候 spawn、怎么管理状态"全靠团队自己摸索。

**5. 从开发到生产的距离有多远？**

即使借助开源框架解决了上述问题，仍然面临部署运维、监控告警、弹性扩容、灰度发布等一系列工程化挑战。一个原型到生产级服务之间，往往是 3-6 个月的工程投入。

### 问题根源：两种不同的工程形态
这五个问题的根源是同一件事：**个人助手型 Agent 和企业级 Agent 是两种完全不同的工程形态**，用同一套假设去应对两种场景必然碰壁。

| 维度 | 个人助手型 Agent | 企业级 Agent |
| --- | --- | --- |
| 部署形态 | 单用户单进程，状态全在本机 | 多租户、水平扩容、状态分布式存储 |
| 安全边界 | 本机可信环境，执行无风险 | 生产环境需要严格的沙箱和权限隔离 |
| 运维可观测 | 自己看日志即可 | 记忆落盘、会话可审计、状态变更可追踪 |
| Token 经济 | 对延迟和费用不敏感 | 每一次无效的上下文重推都是真实的成本开销 |
| 迭代速度 | 改代码重启即生效 | 需要灰度发布、配置化热更新 |

## Agnetic 自主规划的核心特性
### 自主规划与动态决策
**能力描述**：智能体接收到复杂任务后，能够自动将其拆解为若干子任务，生成结构化的执行计划（Plan），并按照优先级逐步执行。执行过程中如果发现原计划不可行，会自动修订计划并继续推进。

**业务价值**：

+ **降低使用门槛**：用户只需描述最终目标，无需手动拆解步骤，AI 自主完成从目标到交付的全过程。
+ **提升任务成功率**：遇到子任务失败时，智能体可以自主调整策略、尝试备选方案，而非直接终止。
+ **支持复杂业务流程**：如"分析上月销售数据，找出异常门店，生成整改建议并发送给区域经理"这样的多步骤任务，一次交代即可完成。

### 多工具协作与技能编排
**能力描述**：平台支持为智能体配置丰富的工具集——企业知识库检索、外部 API 调用（MCP/HTTP）、子工作流编排、子智能体委派等。智能体在执行过程中，根据当前任务需要自主选择合适的工具调用。

**业务价值**：

+ **打通企业数据孤岛**：智能体可以同时访问 CRM、ERP、知识库、内部 API 等多个系统，实现跨系统的自动化操作。
+ **能力可插拔扩展**：新增一个业务系统的对接，只需注册一个新工具，无需修改智能体的核心逻辑。
+ **子 Agent 委派**：复杂任务可拆分给多个专业子智能体并行执行（如法务审查、财务核算、合规检查同时进行），主智能体协调汇总。

### 智能上下文管理与长期记忆
**能力描述**：内置三层渐进式上下文压缩管道（Snip → Microcompact → Autocompact），自动管理对话历史的膨胀问题。同时支持跨会话的长期记忆提取与检索，智能体能"记住"用户的偏好和历史交互。

**业务价值**：

+ **支持超长任务执行**：即使任务涉及数十轮工具调用，也不会因为上下文溢出而丢失关键信息。
+ **跨会话记忆延续**：用户下次对话时，智能体仍然记得之前的沟通结果和偏好设置，无需重复说明。
+ **降低 Token 成本**：智能压缩过期信息，保留关键事实，在保证执行质量的同时减少 API 调用费用。
+ **动态适配模型能力**：根据实际使用的模型上下文窗口大小自动校准压缩策略，避免小模型溢出或大模型过早压缩。

### 流式输出与实时反馈
**能力描述**：智能体在执行过程中支持流式输出（SSE），用户可以实时看到执行进展、中间结果和最终答案，而非等待全部完成后才返回。

**业务价值**：

+ **用户体验优越**：复杂任务执行时用户不会面对"空白等待"，而是能实时看到智能体的思考和进展。
+ **支持人机协作**：通过澄清（Clarify）和审批（Approval）机制，智能体在关键决策点可以暂停并征求用户确认。
+ **透明可控**：企业管理员可以监控智能体的每一步操作，确保执行过程符合业务规范。

### 中心化部署的工程级保障
**能力描述**：与开源框架需要自行部署维护不同，百宝箱平台以**中心化 SaaS 服务**方式提供 Agentic 能力，企业无需关注基础设施。

**业务价值**：

+ **零运维成本**：无需搭建集群、管理线程池、处理分布式状态同步，平台全部托管。
+ **企业级高可用**：内置线程池隔离（主流程与后台任务分离）、熔断保护、优雅降级，确保服务稳定性。
+ **安全合规**：租户隔离、数据加密、操作审计，满足企业级安全要求。
+ **弹性扩缩容**：平台自动应对流量波动，企业无需预估和预留计算资源。
