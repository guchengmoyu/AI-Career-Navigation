HTTP 请求节点用于在工作流中通过 HTTP 协议向外部服务发送 API 请求，实现数据的获取、提交和交互。相比插件节点，HTTP 请求节点无需提前注册，支持直接配置请求地址和参数，适用于轻量级、临时性的外部接口调用场景。

## 添加 HTTP 请求节点
1. 在工作流流程逻辑页面，点击页面下方快捷工具栏的 **+ 添加节点 > HTTP 请求**。
2. 根据自身需求完成 HTTP 请求节点与其他节点的串联。

## 配置 HTTP 请求节点
1. 在流程逻辑页面，找到并点击目标 HTTP 请求节点，唤起配置面板。
2. 在配置面板中完成 API 地址、请求头、请求参数、鉴权、请求体等配置后即可。

## 常见问题
**如何快速配置已有接口？**

可通过节点顶部的"导入 cURL"功能，将已有的 cURL 命令粘贴导入，系统将自动解析请求方式、地址、请求头和请求体等信息并填入对应配置项。

**如何解决 HTTP 请求超时问题？**

可通过调大超时设置来解决。若接口响应较慢，建议适当增大超时时间。同时确认"失败时重试"已开启，以应对偶发的网络波动。

**如何确保 HTTP 请求的安全性？**

可通过启用鉴权配置来确保请求安全，根据目标接口的认证要求选择合适的鉴权方式（API Key、Bearer Token、Basic Auth 或 OAuth2.0）。

**节点运行失败后如何保证工作流继续执行？**

可通过配置"异常处理"为"默认值"或"异常分支"模式。选择"默认值"时，节点失败后将输出预设内容并继续执行下游节点；选择"异常分支"时，可编排专门的异常处理流程。
