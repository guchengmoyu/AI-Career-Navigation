## 2. 我方独立复核（不采信单方声明，逐项实测）

复核方式：从 `origin/ai-career-dataset` 导出 seed / core 的 `knowledge_cards.csv`、`retrieval_eval.csv` 及 7 张主表，与本机 v1.1.0 同名文件做**主键集合 + 非元数据列逐值比对**。

### 2.1 悬空引用 —— 上游声明属实 ✅

| 版本 | v1.1.0（我们用的） | v1.2.0（远端） |
|---|---|---|
| `v0.2-seed` | 50 条用例中 **39 条悬空** | **0 条** |
| `v0.5-core` | 100 条用例中 **48 条悬空** | **0 条** |
| `v1.0-full` | 200 条用例中 **0 条** | 0 条（本就自洽） |

→ 我们报告中"48 条 / 39 条"的数字**在 v1.1.0 时点上是准确的**，但**不是当前状态**。

### 2.2 岗位卡拆分 —— 上游声明属实 ✅

| 版本 | v1.1.0 | v1.2.0 |
|---|---|---|
| seed | 全部 200 张卡均为 `skill_level` | skill_level 90 / learning_resource 60 / **role_skill 9 + role_adjacent_skill 21** / trend 10 / ethics 10 |
| core | 600 张 = skill_level 300 + learning_resource 300 | skill_level 250 / learning_resource 200 / **role_skill 27 + role_adjacent_skill 63** / trend 30 / ethics 30 |
| **full** | skill_level 300 / learning_resource 600 / **role_skill 180** / trend 60 / ethics 60 | 同上，但 **role_skill 54 + role_adjacent_skill 126** |

→ 54/126 拆分与上游 CHANGELOG 一致；**卡并未删除，只是改了类目语义**，并附带声明"不参与当前岗位匹配评分"。

### 2.3 内容是否真的变了？—— 只是升版本号，值没动 ✅

对 7 张主表逐值比对（排除 `schema_version`、`generated_at` 两个元数据列）：

| 表 | 行数 | 主键集合 | **非元数据列内容差异** |
|---|---|---|---|
| `skills.csv` | 一致 | 一致 | **0 行** |
| `jobs.csv` | 一致 | 一致 | **0 行** |
| `users.csv` | 一致 | 一致 | **0 行** |
| `job_skills.csv` | 一致 | 一致 | **0 行** |
| `role_skills.csv` | 一致 | 一致 | **0 行** |
| `trend_snapshots.csv` | 一致 | 一致 | **0 行** |
| `learning_resources.csv` | 一致 | **不一致**（各独有 23/33 条） | 共有的行 **0 行差异** |

→ 结论：v1.2.0 对 seed / core 的改动是 **① `schema_version` 升号 + ② 知识卡按类别分层重选 + ③ 学习资源换了一批子集**，**不是重新生成数值**。我们依赖的 `skill_level` 卡、`jobs`、`job_skills`、`role_skills` **完全未变**。

### 2.4 根因是否已消除？—— 已消除 ✅

我们定位的根因代码 `generate_dataset.mjs:1497` 的 `knowledgeCards.slice(0, config.knowledge)` **在 v1.2.0 中已不存在**，被 `selectKnowledgeCardsForVersion()`（L1539）取代，其逻辑按 `category` 逐类过滤取数——**正是我们建议的"按类别分层抽样"**。

## 4. 能解决 / 不能解决我们当下的哪些问题

### ✅ 能解决

1. **报告"原料缺陷"叙事的时效性风险**——目前报告写的是"存在两项缺陷"，若不更新，会被质疑"用的是旧版本 / 没跟进修复"。改为 **"缺陷发现 → 反馈 → v1.2.0 修复"闭环**后，反而成为加分项。
2. **为"只使用技能等级卡"提供外部背书**——上游交接文档明文写"只使用技能等级卡的既有实验不受影响"，可直接引用，省去自证。
3. **数据质量章节多一份权威旁证**——新增质量报告 v1.2.0 明确"22 条已核验课程 / 98 条目录主题卡团队派生"，**与我们校正后的 22 / 98 完全一致**，可交叉印证。
4. **补上"校验体系"这条最佳实践**——v1.2.0 新增的 `knowledge_category_mix`、`knowledge_*_relation` 校验，正是我们报告"引用完整 ≠ 数据自洽"结论的落地体现，可作为改进方向的现成例证。

### ❌ 不能解决

1. **严格引用 0/54（KC 卡 ID 未被引用）**——知识卡 ID 与文档正文结构均未变，此问题在数据侧无解，仍须按既定方案**双口径并陈 + 如实暴露**。
2. **自定义数据属性未配置（§3.4）**——平台侧配置问题，与数据集版本无关。
3. **平台实测覆盖率仅 27%**——取决于我们是否补做其余 146 条的命中测试，与版本无关。
