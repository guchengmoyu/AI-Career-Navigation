# 知识库卡片组织方案对比

样例技能：**Python编程（SKILL-001）** · 所属领域：编程与计算基础
数据来源：`ai-career-dataset/data/v0.5-core/csv/knowledge_cards.csv`（600 张卡片，其中 300 张 skill_level）

---

## 一、两种方案各产出什么

| | 方案A：一卡一片 | 方案B：一技能一篇 |
|---|---|---|
| 组织逻辑 | 1 张卡片 = 1 篇文档 | 1 个技能 = 1 篇文档 |
| 本技能产出 | 5 篇 | 1 篇 |
| 全库规模（技能类） | 300 篇 | 60 篇 |
| 单篇字数 | 约 200 字 | 约 500 字 |
| 等级信息 | 分散在 5 篇里 | 集中在一篇内 |
| 元数据字段 | 每篇带卡片ID/证据等级 | 集中在文末 |

产出文件：

```
方案A_一卡一片/KC-SKILL-001-L1.md      ← 只讲等级1
              KC-SKILL-001-L2.md      ← 只讲等级2
              KC-SKILL-001-L3.md
              KC-SKILL-001-L4.md
              KC-SKILL-001-L5.md
方案B_一技能一篇/SKILL-001_Python编程.md  ← 内含等级1—5
```

---

## 二、关键数据：这张卡片表本身的形态

在讨论方案之前，必须先看清原料。全部 300 张 skill_level 卡片实测：

- **句式模板只有 3 种**，在 300 张卡片里反复复用：

| 张数 | 句式 |
|---:|---|
| 120 | 学习者理解基础概念并在指导下完成任务 |
| 120 | 学习者独立完成常见任务、解释方法并处理异常 |
| 60 | 学习者设计复杂方案、评估风险并指导他人 |

- **同一个技能内部，等级文案按 2+2+1 分组重复**（以 Python编程 为例）：

| 等级对 | 文本 Jaccard 相似度 | 判定 |
|---|---:|---|
| L1 vs L2 | **0.914** | 近乎重复 |
| L2 vs L3 | 0.593 | 有区分 |
| L3 vs L4 | **0.918** | 近乎重复 |
| L4 vs L5 | 0.557 | 有区分 |

也就是说，**5 个等级的卡片，实际只承载了 3 种不同信息**。60 个技能全部遵循这个模式。

## 三、检索行为差异（用真实评测用例 RETR-001）

```
query   = 如何判断Python编程等级1，需要哪些证据？
期望答案 = KC-SKILL-001-L1
```

用全库候选池做检索模拟（字符 bigram 覆盖率，仅用于相对比较）：

### 方案A（候选池 300 片）

| 排名 | 命中切片 | 得分 | 技能 |
|---:|---|---:|---|
| Top1 | KC-SKILL-001-L1 | 0.5500 | SKILL-001 ← 期望答案 |
| Top2 | KC-SKILL-001-L2 | 0.5000 | SKILL-001 |
| Top3 | KC-SKILL-001-L3 | 0.5000 | SKILL-001 |
| Top4 | KC-SKILL-001-L4 | 0.5000 | SKILL-001 |
| Top5 | KC-SKILL-001-L5 | 0.5000 | SKILL-001 |

**Top5 全部来自同一个技能（5/5）。** 正确答案在里面，但它上面、下面躺着 4 条几乎一样的兄弟切片。

### 方案B（候选池 60 篇）

| 排名 | 命中文档 | 得分 | 技能 |
|---:|---|---:|---|
| Top1 | Python编程 | 0.5000 | SKILL-001 ← 期望答案所在篇 |
| Top2 | 软件工程 | 0.1500 | SKILL-007 |
| Top3 | 特征工程 | 0.1500 | SKILL-020 |
| Top4 | 数据结构与算法 | 0.1000 | SKILL-002 |
| Top5 | 面向对象设计 | 0.1000 | SKILL-003 |

**Top1 与 Top2 之间出现 3.3 倍断层。** Top5 覆盖 5 个不同技能。

## 四、三个决定性差异

### 1. 冗余能不能被阈值过滤掉

这是最硬的一条：

| | Top1 得分 | Top2 得分 | 可切分的阈值窗口 |
|---|---:|---:|---|
| 方案A | 0.55 | 0.50 | **0.05 宽**（0.50 ~ 0.55） |
| 方案B | 0.50 | 0.15 | **0.35 宽**（0.15 ~ 0.50） |

方案A 想"只留正确答案、滤掉冗余"，阈值必须卡在 0.50 和 0.55 之间——一个极窄的窗口。阈值设 0.5，5 条全留（等于没滤）；设 0.55，正确答案也被滤掉。

方案B 的窗口宽 7 倍，一个 0.3 的阈值就能干净地只留 Top1。

**结论：方案A 产生的冗余，在检索层无法自动消除；方案B 的噪音可以被一刀切掉。**

### 2. 喂给模型的上下文是否完整

- **方案A 的 Top1**：只有一句话——"等级1要求学习者理解基础概念并在指导下完成任务"，约 60 字。模型无法回答"等级1和等级2差在哪""学到什么程度够用"。
- **方案B 的 Top1**：一篇含 5 个等级的完整文档，约 500 字。模型能横向对比、能回答梯度问题。

而你的 100 条评测 query 里，真实提问方式是"**学到什么程度算够用**"「岗位匹配中如何体现」——**这些都需要看到多个等级才能回答**。

### 3. 对评测指标的影响（这条最容易被忽略）

队友给的验收规则是：

> `expected_card_ids` 至少一项出现在 Top5，且回答引用来源 ID

注意这是一个 **recall@5** 口径——它只问"正确答案在不在里面"，**不问"里面有没有废话"**。

于是出现一个反直觉的结果：

| | 方案A | 方案B |
|---|---|---|
| 期望答案是否在 Top5 | 是 | 是 |
| recall@5 | 通过 | 通过 |
| 但 Top5 里有几条有用信息 | **1 条**（另 4 条是同一技能的重复等级） | **1 条**（另 4 条是不相关技能） |
| 严格口径 precision@5 | 0.2 | 0.2 |

**两种方案在队友的评测口径下无法区分。** 这套指标能测出"有没有召回"，测不出"召回得干不干净"。

所以你选的方案，**必须在报告里用自定义指标证明**，至少要加：

- **等级精确命中率**：L1 的 query 是否命中 L1（而不是 L2）
- **同源冗余率**：Top5 里有几条来自同一个技能
- **答案可回答性**：Top1 文本是否足以回答该 query（人工判定）

否则答辩时你会遇到一个尴尬：**你花力气优化了方案，评测分数却没变。**

## 五、方案B 附带暴露的一个数据问题

把 5 个等级合成一篇之后，一件事变得**肉眼可见**：

> 在 `SKILL-001_Python编程.md` 里，**等级1 和等级2 的正文一字不差**（除数字外），**等级3 和等级4 也是**。

这个缺陷在方案A 下是隐藏的——它藏在 300 个切片的相似度排序里，你只会觉得"检索结果有点雷同"，但找不到原因。**合并成一篇后，你翻开文档就看见了。**

这对你的报告是好事：**"通过重组暴露了原料的结构性缺陷，并据此提出修复建议"**，这是评估报告里很有分量的一节。

## 六、我的建议

> ⚠️ **本节结论已被修正。** 后续对全部 5 类卡片、200 条 query 做了细测，发现"聚合"只在**能力等级证据**一类上有效，对**岗位匹配反而更差**，对**资源推荐不适用**；而**趋势解读 / 隐私边界**虽不受组织方式影响，却存在最严重的模板干扰问题。
> 请以 [`五类query完整对比.md`](./五类query完整对比.md) 为准。本节保留作为"初判 → 细测 → 修正"的研究过程记录。

**方案B（一技能一篇）作为主方案，但要配套三件事：**

1. **保留卡片 ID 映射**：文档里记下"本篇聚合自 KC-SKILL-001-L1 ~ L5"，这样队友的 `expected_card_ids` 评测口径仍能对齐。
2. **自定义评测指标**：在上面第四节列的三项，否则无法证明方案B 更优。
3. **向数据方反馈 L1=L2 / L3=L4 的模板重复问题**：建议把 5 个等级的描述改成真正递进的 5 档（比如 L1 认识语法、L2 能改现成代码、L3 能独立实现、L4 能设计方案、L5 能定标准）。

**但方案A 不要丢掉**——它应该是你报告里的**对照组基线**。同一批 100 条 query 跑两个方案、出两组数字，这份对比实验本身就是报告的核心章节。

---

*注：本文所有检索分数为字符 bigram 覆盖率模拟，用于揭示两种组织方式的相对差异，不等同于百宝箱平台的实际向量检索得分。真实数值需在平台「命中测试」页实测。*
